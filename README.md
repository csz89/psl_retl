# PSL Rater

Статический сайт: один `index.html` + `config.js`. Сервера и сборки нет, поэтому он без настроек работает на Vercel, GitHub Pages и любом хостинге.

| Файл | Зачем |
|---|---|
| `index.html` | весь сайт (страницы, модель, аккаунты) |
| `config.js` | **сюда вписывается Google Client ID** |
| `serve.js` | локальный сервер для проверки на своём компьютере (`node serve.js`, затем http://localhost:5173) |
| `.gitignore` | не пускает в репозиторий фото |

## 1. Репозиторий на GitHub

**Сначала про фото.** В локальном коммите этой папки уже лежит файл `03b33f…jpg` с лицом человека, а рядом есть `parenL.jpg`. Если просто сделать `git push`, эти фото станут публичными вместе с историей. Поэтому самый безопасный путь начать репозиторий заново, пока ничего не отправлено:

```powershell
cd D:\mogs
Remove-Item -Recurse -Force .git
git init -b main
git add .
git status        # проверьте список: только index.html, config.js, serve.js, README.md, .gitignore
git commit -m "PSL Rater"
```

Затем на github.com создайте пустой репозиторий (например `psl-rater`, без README и .gitignore) и:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/psl-rater.git
git push -u origin main
```

Файлы `*.jpg`, `*.png` и т. п. теперь игнорируются, но всё равно проверяйте `git status` перед каждым коммитом.

## 2. Vercel

1. vercel.com → **Add New… → Project** → войдите через GitHub и выберите репозиторий.
2. **Framework Preset: Other.** Поля Build Command, Output Directory и Install Command оставьте пустыми.
3. **Deploy.** Через минуту сайт будет доступен по адресу вида `https://psl-rater.vercel.app`. Он обновляется сам после каждого `git push` в ветку `main`.

## 3. Вход через Google

Нужен бесплатный Client ID. Секретный ключ не нужен.

1. Откройте https://console.cloud.google.com и создайте проект.
2. **APIs & Services → OAuth consent screen** (в новом интерфейсе Google Auth Platform):
   - Тип пользователей: **External**.
   - Название приложения, ваша почта поддержки и почта разработчика.
   - Ссылка на политику конфиденциальности (если просят): `https://ВАШ-САЙТ.vercel.app/#/privacy`.
   - Пока приложение в режиме **Testing**, войти смогут только аккаунты из списка *Test users* (добавьте свой). Чтобы пускать всех, нажмите **Publish app**: для базовых данных (email, profile, openid) проверка Google не требуется.
3. **Credentials → Create credentials → OAuth client ID → Web application.**
   - **Authorized JavaScript origins**: добавьте `https://ВАШ-САЙТ.vercel.app` (без `/` в конце и без пути) и для локальной проверки `http://localhost:5173`.
   - **Authorized redirect URIs** оставьте пустым: кнопка работает через всплывающее окно.
4. Скопируйте **Client ID** (оканчивается на `.apps.googleusercontent.com`) и вставьте в `config.js`:

   ```js
   googleClientId: "1234567890-abcdefg.apps.googleusercontent.com",
   ```
5. `git add config.js && git commit -m "Google Client ID" && git push`. Vercel обновит сайт, и кнопка станет активной.

Изменения в консоли Google иногда применяются не сразу (от нескольких минут до пары часов).

### Если не работает

| Симптом | Причина |
|---|---|
| `origin_mismatch` или «The given origin is not allowed» | адрес сайта не добавлен в Authorized JavaScript origins или написан иначе (http вместо https, лишний `/`, другой поддомен) |
| «Доступ заблокирован: приложение не прошло проверку» | приложение в режиме Testing, а вашего аккаунта нет в Test users, либо не нажата Publish app |
| кнопка Google серая, написано «не настроен» | `config.js` пустой или не попал в репозиторий |
| работает на основном адресе, но не на ссылке предпросмотра | у каждой ветки/коммита на Vercel свой адрес, в Google добавлен только основной |
| не работает при открытии `index.html` двойным щелчком | Google не пускает страницы с `file://`, запустите `node serve.js` |

Если Google не принимает адрес `*.vercel.app` на экране согласия, подключите свой домен (Vercel → Settings → Domains) и используйте его.

## 4. Онлайн-батлы и магазин (Supabase)

Страница «Онлайн»: бой 1 на 1 между двумя живыми игроками, ранги от Рекрута до Титана, рейтинг лиц. Нужен бесплатный проект Supabase (общая база для всех игроков).

**Как проходит бой.** Игрок нажимает «Найти соперника» (нужна галочка согласия). Ему подбирают игрока **того же пола и того же ранга** (если ждать дольше 10 секунд, то и соседнего ранга, но не дальше: Рекрут никогда не встретит Титана). Появляются два окна: «Ты» и «Соперник». В своём окне автоматически включается камера: игрок смотрит в овал, жмёт «Сделать снимок» (обратный отсчёт 3-2-1), при необходимости «Переснять», и жмёт «Определить рейт». **Фото из файла в бою не принимается**: загрузки, перетаскивания и вставки нет, лицо берётся только с живой камеры. Когда рейт определили оба, побеждает тот, у кого он выше, **даже на 0,1**. У проигравшего лицо становится чёрно-белым и появляется надпись **MOGGED**. Победа +100 очков, поражение −50 (ниже нуля не падает), ничья 0. 500 очков = 1 ранг, всего 8. Если соперник за 3 минуты не определил рейт или вышел после того, как вы поставили лицо, вам засчитывается победа (неявка).

**Что уходит на сервер:** ник, пол, число PSL, очки и маленькая копия лица (квадрат около 256 пикселей), которую видит соперник. Копия стирается через 5 минут после боя. Видео не записывается и не отправляется, кадр целиком тоже. Камера выключается сразу после снимка и в конце боя. Камере нужен https (на Vercel он есть) и разрешение браузера; без камеры онлайн-бой недоступен.

1. https://supabase.com → **New project**.
2. **SQL Editor → New query**, вставьте весь файл `supabase.sql`, нажмите **Run**. Можно запускать повторно и поверх старой версии: игроки и очки сохраняются.
3. **Authentication → Sign In / Providers → Google**: включите и в **Client IDs** вставьте тот же Client ID, что в `config.js`. Client Secret можно не заполнять.
4. **Project Settings → API Keys**: скопируйте **Project URL** и **Publishable key** (или anon public) в `config.js`:
   ```js
   supabaseUrl: "https://abcdefgh.supabase.co",
   supabaseAnonKey: "sb_publishable_...",
   ```
   Эти ключи публичные. **service_role** и **secret** ключи никуда не вставляйте.
5. `git add . && git commit -m "Online battles" && git push`. Через минуту Vercel обновит сайт.
6. (При обновлении с прошлой версии просто выполните новый `supabase.sql` ещё раз: Рета и магазин добавятся, игроки и очки сохранятся.)
7. Откройте `/#/online`: войдите через Google, придумайте ник, поставьте галочку и нажмите «Найти соперника». Для проверки нужны два аккаунта на двух устройствах (или обычное окно и окно инкогнито).

**Рета и магазин (страница «Магазин»).** Рета это местные очки (на сайте они нарисованы как упаковка Реты). За каждую победу в онлайн-бое сервер начисляет 100 Реты. В магазине за неё покупают анимации победы (могг), рамки аватара, звания, стили ника и фоны профиля. Баланс, покупки и надетое хранятся на сервере: цены берутся из таблицы `shop_items`, купить без денег или надеть чужое нельзя даже из консоли браузера. Чтобы поменять цену, измените число в `supabase.sql` (блок `insert into public.shop_items`) и снова нажмите Run. Новый предмет нужно ещё описать в `index.html` (объект `SHOP`): сайт показывает только те предметы, которые знает.

**Жалобы.** Кнопка «Пожаловаться на фото соперника» сохраняет копию фото в таблицу `reports` (Supabase → Table Editor). Смотрите её время от времени. Если фото неприемлемое, удалите игрока в Authentication → Users.

Чтобы поменять очки или ранги, правьте числа в `supabase.sql` (100, 50, 500) и такие же константы `RANK_PTS`, `WIN_PTS`, `LOSS_PTS` в `index.html`, затем снова запустите SQL.

**Ограничения.** PSL считается в браузере игрока, и сервер ему верит: тот, кто разбирается в коде, может отправить выдуманное число. Фото соперника сервер не проверяет, поэтому в бою возможны неприемлемые снимки (отсюда жалобы). Для серьёзного соревнования нужны серверная оценка и модерация.

## 5. Рейты, игры, задания и донат

**Что это.** Расходуемые попытки хранятся на сервере (Supabase) и привязаны к аккаунту Google:
- **Рейт** тратится на оценку одного фото (в режиме «Сравнение» на каждое из двух). Списывается только после успешного анализа: если лицо не найдено, ничего не тратится. Без рейтов результат не показывается, открывается окно с бонусом и покупкой.
- **Игра** тратится на один онлайн-бой (оба игрока платят по игре, когда бой найден). Если бой отменился и никто не определил рейт, игра возвращается.
- Новому игроку дают **10 рейтов и 10 игр**. Каждый день (по UTC) можно забрать бесплатно **+5 рейтов и +10 игр** на странице «Бонусы».
- **Задания недели** (страница «Бонусы», сбрасываются в понедельник по UTC) дают Рету: выиграй мог-батл +200, сделай рейт +50, сравни два лица +80, сыграй 3 боя +150 и другие. Прогресс считает сервер.
- Все цифры (награды, пакеты, цены) лежат в начале `supabase.sql`: измените и нажмите Run.

**Донат (покупка рейтов и игр).** Минимальный пакет: 20 рейтов за $1,20. Пакеты: рейты 20/60/150/400, игры 20/60/150. Цены есть в шести валютах (USD, EUR, UAH, RUB, PLN, KZT), страница сама выбирает валюту по часовому поясу, её можно сменить. Региональные цены в `supabase.sql` ориентировочные: подберите их под своих игроков (сумма в минимальных единицах, 4500 = 45,00).

Как проходит оплата: сайт просит у `/api/checkout` ссылку на оплату, платёжная система (Stripe или LiqPay) принимает деньги на своей странице, потом сама сообщает серверу (`/api/stripe-webhook`, `/api/liqpay-callback`), и только после проверки подписи сервер начисляет пакет. Цену выбирает сервер по своей таблице, браузер её подменить не может, один платёж не засчитывается дважды.

**Быстрый старт: гривна через LiqPay** (так сейчас настроен `config.js`: `payProviders: ["liqpay"]`, на странице «Донат» остаются UAH, USD и EUR, гривна первая).
1. Нужен аккаунт LiqPay (liqpay.ua) с подключённым магазином. Обычно для приёма платежей нужен ФОП или юридическое лицо: условия проверьте у LiqPay.
2. В кабинете LiqPay откройте магазин → **API** и возьмите **Public key** и **Private key**.
3. В Vercel (проект → Settings → Environment Variables) добавьте: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY`. Для первой проверки добавьте ещё `LIQPAY_ALLOW_SANDBOX` со значением `1`: тогда платёж идёт в тестовом режиме LiqPay и деньги не списываются (тестовая карта есть в документации LiqPay, например 4242 4242 4242 4242).
4. Vercel применяет переменные только к новым сборкам: после добавления нажмите Deployments → ⋯ → **Redeploy**.
5. Проверьте покупку 20 рейтов за 45 ₴: после тестовой оплаты баланс на странице «Донат» должен вырасти за несколько секунд.
6. Для приёма настоящих денег удалите `LIQPAY_ALLOW_SANDBOX` и снова сделайте Redeploy. Адрес уведомлений (`/api/liqpay-callback`) сайт передаёт LiqPay сам, в кабинете его настраивать не нужно.

Полный список (Stripe и остальное):
Чтобы включить приём платежей (без этого страница «Донат» показывает цены, но кнопки «Оплата не подключена»):
1. В Vercel: проект → **Settings → Environment Variables** добавьте (для Production):
   - `SUPABASE_URL` (тот же, что в `config.js`), `SUPABASE_ANON_KEY` (publishable/anon ключ), **`SUPABASE_SERVICE_ROLE_KEY`** (Supabase → Project Settings → API Keys → secret/service_role). Это секретный ключ: только здесь, никогда в `config.js` и в репозиторий.
   - Для карт: `STRIPE_SECRET_KEY` (sk_live_... или sk_test_...) и `STRIPE_WEBHOOK_SECRET`. В Stripe: Developers → Webhooks → Add endpoint `https://ВАШ-САЙТ.vercel.app/api/stripe-webhook`, события `checkout.session.completed` и `checkout.session.async_payment_succeeded`, оттуда берите whsec_...
   - Для гривны: `LIQPAY_PUBLIC_KEY` и `LIQPAY_PRIVATE_KEY` (кабинет LiqPay → магазин → API). Для проверки можно временно `LIQPAY_ALLOW_SANDBOX=1`, в рабочем режиме уберите.
   - По желанию `SITE_URL` (`https://ВАШ-САЙТ.vercel.app`).
2. В `config.js` впишите способы, которые настроили: `payProviders: ["stripe", "liqpay"]` (можно один). Stripe принимает USD, EUR, PLN и другие (доступность RUB, KZT и UAH зависит от вашего аккаунта), LiqPay только UAH, USD, EUR.
3. Выполните новый `supabase.sql` (Run), сделайте `git push`. Сначала проверьте на тестовых ключах Stripe (sk_test_..., карта 4242 4242 4242 4242): после оплаты баланс должен вырасти за несколько секунд.

Важно знать:
- Принимать деньги может только тот, у кого есть подходящий аккаунт: Stripe доступен не во всех странах (например, не открывается для предпринимателей из Украины и России), поэтому для гривны и рублей обычно берут местные сервисы. LiqPay рассчитан на украинские аккаунты, для России сейчас в сайте нет готового способа.
- Продажа цифровых услуг это бизнес: налоги, договор-оферта, возвраты и условия платёжной системы на вас. На странице есть короткая оговорка (начисляется сразу, деньгами не возвращается), юридический текст подготовьте сами.
- Проверка рейтов выполняется в браузере: модель считает оценку на устройстве игрока, и тот, кто разбирается в коде, может обойти списание. Для серьёзной защиты оценку нужно считать на сервере.
- Я проверял платёжные функции на тестовых данных и по описанию платёжных систем, но не с реальными аккаунтами Stripe и LiqPay. Перед открытием обязательно сделайте тестовую оплату.

## 6. Администратор

Аккаунт **renkonkop@gmail.com** (вход через Google) считается администратором. Это решает сервер по списку в таблице `admins` (блок в начале `supabase.sql`): список сверяется с адресом, который подтвердил Google, поэтому зарегистрироваться по email с чужим адресом нельзя.

Что получает администратор:
- **Безлимит.** Рейты, игры и Рета не списываются, в магазине можно брать и надевать всё бесплатно, в шапке вместо чисел знак ∞. Играть онлайн можно с нулём игр.
- **Страница «Админ»** (пункт меню виден только администратору): поиск игрока по нику, почте или id; карточка с почтой, балансами и украшениями; выдать или забрать Рету, рейты и игры (отрицательное число забирает); выдать или забрать любую анимацию и украшение; журнал последних действий (таблица `admin_log`).
- Права проверяются сервером при каждом действии: если обычный игрок откроет страницу вручную, его отправит на главную, а вызов из консоли сервер отклонит.

Чтобы добавить ещё одного администратора, впишите его почту (маленькими буквами) в строку `insert into public.admins` в `supabase.sql`, нажмите Run, и пусть он войдёт через Google с этой почтой. Убрать: удалите строку из таблицы `admins` в Table Editor.

## 6.0. Открыть сразу три кейса

Рядом с кнопкой «Открыть кейс» есть кнопка **«Открыть ×3»** (цена втрое больше). Сервер выполняет три открытия одной функцией `open_cases` в одной транзакции: Рета списывается за все три сразу, а если её не хватает хотя бы на одно, не списывается ничего. На экране три рулетки крутятся одновременно (кнопка «Пропустить» останавливает все), потом показываются три приза рядом, у каждого своя кнопка «Надеть», а ниже «Ещё ×3». Нужно один раз выполнить `supabase.sql` заново.

## 6.1. Кейсы

В меню появилась страница **«Кейсы»**. Сейчас там один кейс **Holy IQ** за 500 Реты. Предмет выбирает сервер (функция `open_case`), браузер только показывает рулетку: она ведёт себя как рулетка рейта (тот же набор «сценариев»: притормаживает на соседнем предмете, дрожит, возвращается), только в другом оформлении.

Что внутри (шанс = вес в процентах):
- Чёрно-белая рамка аватара, **обычная**, 40%
- Звания «Ларп» и «Нет», **редкие**, по 22%
- Звание «Foid Slayer», **эпическое**, 7% (реже, чем «Ларп» и «Нет»)
- Стиль ника «Чёрное свечение», **эпическое**, 5%
- Фон профиля «Девять яблок» (9 яблок стоят на фоне и крутятся вокруг своей оси), **легендарный**, 3%
- Анимация могга **Holy IQ**, **мифическая**, 1%: над победителем кружат яблоки, а его IQ растёт без остановки; у проигравшего остаётся только «70 IQ»

Предметы из кейсов в магазине не продаются (там они видны с пометкой «Только из кейса»). Если выпал предмет, который уже есть, копия не пропадает, а ложится в **инвентарь** (см. ниже). Администратору кейсы бесплатны, а любой предмет можно выдать на странице «Админ».

Цену, шансы и возврат можно менять в блоке «кейс Holy IQ» в `supabase.sql` (или в Table Editor, таблицы `cases` и `case_items`). Чтобы кейсы заработали, после обновления сайта **один раз выполните `supabase.sql` заново** (Run в SQL Editor): он только добавляет новое и не трогает балансы.

## 6.2. Кейс «ТикТок философия»

Второй кейс, тоже **500 Реты**, на тему философии и литературы:

- Звание «Бездарный» и рамка аватара «Уроборос» (злая змея пожирает саму себя), **редкие**, по 14%

## 6.3. Инвентарь и апгрейдер

- **Страница «Инвентарь»**: все ваши предметы, повторы тоже (значок ×2, ×3...). Надеть и снять, **продать** одну копию или все повторы за половину стоимости предмета (последняя копия тоже продаётся, предмет тогда пропадает и снимается с игрока), перейти в апгрейдер с этим предметом.
- **Страница «Апгрейд»**: как апгрейдеры в играх с кейсами. Слева выбираете, что отдать (можно несколько предметов и несколько копий), справа выбираете более дорогую цель. Шанс = стоимость отданного / стоимость цели × 95%, не больше 90% и не меньше 2%. Кнопка «Апгрейд»: **сервер** бросает число от 0 до 100, и если оно меньше шанса, цель попадает в инвентарь, иначе отданное пропадает. Стрелка на колесе останавливается ровно в месте этого числа, по клику вращение можно пропустить. Каждый апгрейд пишется в таблицу `upgrade_log`.
- **Стоимость предметов** хранится в колонке `value` таблицы `shop_items`: у товаров магазина это их цена, у предметов из кейсов она задана в блоке «стоимость предметов» в `supabase.sql`. Её можно менять: от неё зависят цена продажи и шанс апгрейда.
- Чтобы это заработало, после обновления сайта **один раз выполните `supabase.sql` заново** (Run в SQL Editor). Уже имеющиеся покупки получат количество 1, балансы не меняются.

## 7. Что важно знать

- **Без аккаунта сайт не работает.** Без входа открыты только главная, справочник рейтов и «Конфиденциальность»: оценка, сравнение, онлайн, магазин и профиль ведут на страницу входа, а брошенное на страницу фото ничего не запускает. Это проверка в браузере (сайт статический), для онлайн-режима и магазина вход дополнительно проверяет сервер.
- **Аккаунты локальные.** Они хранятся в браузере каждого пользователя (`localStorage`), а не на сервере: профиль не переносится между устройствами, а Google-вход подтверждает личность только внутри этого браузера. Токен Google не проверяется на сервере (сервера нет), поэтому это не защита данных, а удобство. Настоящие аккаунты потребуют серверной части (база данных и проверка токена).
- **Лицензия датасета.** Модель обучена на SCUT-FBP5500, который выпущен для научных целей. Прежде чем открывать сайт публично или монетизировать, проверьте условия набора: https://github.com/HCIILAB/SCUT-FBP5500-Database-Release
- **Фото не хранятся и не отправляются:** всё считается в браузере. Но сайт подгружает библиотеку и модели с `cdn.jsdelivr.net` и `storage.googleapis.com`, а шрифт с `fonts.googleapis.com`.
- Развлекательный инструмент: оценка отражает вкус 60 оценщиков, а не объективную истину.
